ASR Pipeline 设计文档

Whisper large-v3 + pyannote speaker diarization · 单机编排 · 断网容灾

概览

一个运行在本地 macOS 上的 Python 编排器，通过 SSH/SCP 控制 GPU 服务器完成音频转写+说话人分离全流程。 所有状态在本地维护，GPU 服务器只是计算资源；服务器随时停机不影响已处理数据，恢复后自动继续。

核心脚本

💻 pipeline_manager.py

Local 主编排器，单进程管理全生命周期

  • 维护 manifest.jsonl 状态清单
  • Upload → Process → Download → Cleanup 循环
  • GPU 不可达时自动跳过，不影响已处理数据
  • 支持 --loop、--status、--init-manifest

⚙️ gpu_worker.py

GPU 由 pipeline_manager 部署并触发

  • ffmpeg m4a→wav 转换（16kHz mono）
  • Whisper large-v3 转写（faster-whisper batched）
  • pyannote speaker-diarization-3.1
  • 模型一次性加载，批内复用
  • 长音频(>30min)自动切块，短音频(<10s)跳过分离

状态机

pending → 等待上传到 GPU
uploading → 正在 scp 传输
uploaded → .m4a 已到达 GPU /root/input/
processing → GPU Worker 正在处理（转换+转写+分离）
done → 结果已下载到 audio_diarized_local/
failed → pending 自动重试（最多 max_retries 次）
恢复机制：启动时 phase_recover() 自动纠正瞬态状态：
uploading → 检查 GPU 上 .m4a 是否存在 → 回退 pending 或推进 uploaded
processing → 检查 GPU 输出是否存在 → 重新入队 uploaded
failed → 未超重试次数则重置为 uploaded

编排器主循环

Phase Recover
纠正因上次运行中断导致的瞬态状态。检查 GPU 上文件真实存在性，恢复 manifest 一致性。
Phase Upload
检查 GPU 磁盘空间（≥2GB free），选 pending 文件 scp 到 /root/input/，标记 uploaded。批次大小可调（默认 10GB）。
Phase Process
SCP gpu_worker.py 到 GPU，SSH 启动 nohup 后台进程处理一批 uploaded 文件。批次大小可调（默认 5 文件）。
Phase Download
检查 GPU output 目录中的 .json 文件，将新完成的 scp 回 audio_diarized_local/，标记 done。失败的标记 failed 并下载 .error。
Phase Cleanup
删除 GPU 上已 done 文件的 .wav 和 .m4a，释放磁盘空间。
Phase Report
打印状态汇总：GPU 在线状态、磁盘用量、各状态文件数、完成百分比。

容灾机制

🟢 GPU 离线

SSH 连接失败 → 跳过所有 GPU 操作阶段。已下载到本地的数据完全不受影响。下一轮循环自动重试。

🟡 GPU 磁盘满

Upload 前检查 free space ≥2GB，不足则暂停上传，优先 Cleanup 释放空间。

🟡 传输中断

scp 异常 → 文件标记 failed → 自动重试（默认 3 次）。manifest 仅记录成功到达的状态。

🔴 Worker 崩溃

GPU worker 意外退出 → mark 为 processing 的文件在下一轮 Recover 中重新入队 → 回退到 uploaded 重新处理。

🔴 本地中断

编排器被 Ctrl+C 或崩溃 → manifest.jsonl 已增量 flush，重启后 phase_recover() 从断点继续。

🔵 重复保护

manifest 初始化时自动检查 audio_diarized_local/ 和 audio_diarized_assemblyai/（所有 {speaker}/{id}.txt），已存在的直接标 done。

已知限制与注意事项

⚠ 非采访类内容

纪录片、单人旁白、现场噪音等场景可能导致 pyannote 过分离（>10 speaker）或大量 UNKNOWN。

⚠ 短段碎片化

VAD filter 将停顿处切分开，对话密集处 "Yeah" "Right" 形成大量短段，但通常不影响内容。

⚠ 长音频 OOM

pyannote 在 >30min 音频上会 OOM（24GB VRAM），已内置 1800s 切块处理。

⚠ 网络限制

GPU 服务器在国内，huggingface.co 被墙。设置 HF_ENDPOINT=https://hf-mirror.com。

💡 单线程瓶颈

Upload/Download 为串行 scp，大文件多时较慢。可考虑并行传输优化。

💡 磁盘空间

GPU 根分区仅 30GB，.wav 文件 ~80MB/个。Cleanup 及时性直接影响吞吐量。
